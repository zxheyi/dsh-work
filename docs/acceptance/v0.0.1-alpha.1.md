# v0.0.1-alpha.1 candidate

Status: unsigned draft candidate; real F13 observation is pending.

This candidate prepares macOS Apple Silicon and Windows x64 bundles for the [F13 observation kit](v0.0.1-alpha.1-observation-kit.md). It does not record participant success or authorize public publication. The older [0.0.1 functional acceptance](release-0.0.1.md) remains historical evidence for its recorded source bytes; it is not a fresh real-provider run of this candidate.

## Candidate contents

- Harness-native conversations, attachment/file results and the existing desktop lifecycle.
- Selected-home custom Agent presets through the native shared preset directory, preserving the initialization choice and source Profile.
- Verified sharp/libvips source, license, build, patch and replacement materials retained with the application.
- Native platform archives with versioned names, SHA-256 checksums and revision-bound package/launch receipts.

The pinned Harness and runtime package versions are unchanged. macOS Intel and Linux packages are not produced. The Windows package is a portable folder; no installer, automatic update, Developer ID notarization or Authenticode claim is made.

## Build and freeze

On the native target platform, run the packaging commands in [desktop packaging](../packaging.md), followed by `pnpm notices:verify-release` and `pnpm package:archive`. The archive step requires successful matching package, material and relocated-launch evidence. CI retains the complete archives separately from diagnostics; archiving and CI upload never publish a GitHub Release.

Freeze the tag only after the version PR and any included compatibility fix have merged and the same main revision has passed native CI. Retrieve both archives from that revision's successful Desktop package run. Verify their checksum files and receipt revision/version, then attach them to the prerelease **draft** with their receipts and this observation kit. The final GitHub draft records the actual commit, CI URL, filenames and SHA-256 values; no placeholder hash is a release receipt.

## Installation and observation

Verify the archive SHA-256 before extraction. On macOS extract the archive and copy the complete `DSH Work.app` to an installation directory. On Windows extract the entire folder and run `DSH Work.exe` from it. Keep all bundled runtime and third-party resources together, including the approximately 216 MiB source materials. Moving only the executable is unsupported.

This is an unsigned candidate. Platform trust prompts and any installation barrier must be recorded by the observer; do not disable system-wide protections to complete the observation. Use a prepared test workspace and synthetic input. Provider configuration and real model use require the participant's own authorized account; keys and private conversations must not enter the observation record.
