## 观察人提前准备

1. 为每位参与者分配 P1 至 P5 编号，不在公开记录中填写姓名、账号、密钥或私人文件。征得参与者同意后再录屏；没有同意时仅记录操作与用语。五人独立进行，彼此不观看前一场操作。
2. 使用独立测试系统账号，或为本次启动设置全新的 Electron `--user-data-dir` 和空的 `DSH_HOME`。每人使用独立目录，避免读取真实 Harness 数据或上一人的会话；不选择复用个人数据。先正常退出已运行的测试应用，通过托盘/菜单明确退出，不仅关闭窗口。
3. 在仓库外建立该参与者的测试目录，例如 `alpha1-observation/P1/`，其中建立 `workspace/` 和 `input/`。将随本操作包提供的[虚构源文件](v0.0.1-alpha.1-source.md)复制到 `input/source.md`，保持内容不变。源文件 SHA-256 为 `8987465d2add63a7a0bdd19e489638426ff7ead7e2ac9ab27f951c2d97679fbd`。`workspace/` 起初为空，将它作为预先建立的工作区，初始停留在该工作区。参与者自行开始新对话并添加 `input/source.md`。
4. 在独立配置中连接可用的真实模型，确认使用成本已获模型账号所有者同意。使用原生权限设置，使本任务的一次范围明确的文件操作需要用户确认，不设置全局自动允许。记录实际模型、模式、权限规则和将出现的操作名称；不安装自动化 fixture 插件来代替真实产品使用。
5. 观察人在独立的预检目录执行一次同样的任务，确认能读入源文件、出现原生授权请求、生成可预览的 Markdown、继续修改并保存。授权只涉及测试目录中的读取或输出写入。如果模型不能稳定触发任务所需授权，记录问题并调整预检配置后重新预检，不能跳过授权步骤宣布 F13 完成。预检结果仍不计入五人观察。
6. 删除预检与正式场次的混用可能：正式场次使用新的参与者目录、空会话和原始源文件。为每场记录 OS 版本、CPU 架构、应用窗口宽高、语言、模型和权限配置。确保输出仅使用虚构材料；不要求访问网络、发送消息、删除文件或执行 Shell 命令。

独立启动的参数沿用[打包启动检查](../../scripts/run-packaged-smoke.mjs)使用的目录隔离方式，正式观察不启用远程调试。以下命令由观察人准备，替换应用的绝对路径与 P1 编号；目录必须是该场次新建的目录。完成模型配置和预检后再交给参与者。

macOS（在独立终端运行）：

```sh
observation_root="$(mktemp -d "${TMPDIR:-/tmp}/dsh-work-alpha1-P1.XXXXXX")"
mkdir -p "$observation_root/empty-harness" "$observation_root/user-data"
DSH_HOME="$observation_root/empty-harness" \
  '/absolute/path/DSH Work.app/Contents/MacOS/DSH Work' \
  "--user-data-dir=$observation_root/user-data"
```

Windows PowerShell（在独立终端运行）：

```powershell
$observationRoot = Join-Path $env:TEMP ("dsh-work-alpha1-P1-" + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path (Join-Path $observationRoot 'empty-harness'), (Join-Path $observationRoot 'user-data') | Out-Null
$env:DSH_HOME = Join-Path $observationRoot 'empty-harness'
& 'C:\absolute\path\DSH Work.exe' "--user-data-dir=$(Join-Path $observationRoot 'user-data')"
```

这些命令是准备说明，写入本文不表示已在本次 alpha 包上执行。保留实际目录位置和检查结果于私有观察记录；不要把含凭据的测试目录作为公开附件上传。

## 只向参与者读出的任务

开场说明：

> 我们在观察这个软件是否容易使用，不是在考你。请按自己的习惯操作，并说说你正在找什么、哪里不明白。我可以重复任务，但不会告诉你按钮在哪里。遇到不愿意执行的操作，可以随时停下。

任务全文：

> 在这个工作区开始一段新对话，加入我提供的 `source.md`，请助手整理一份 Markdown 活动说明。阅读软件请求你确认的那一次文件操作，确认它只涉及本次测试材料后允许执行。查看生成的文件内容及其来源，再让助手做一个修改：把“待确认事项”改成勾选清单，同时保留所有时间和人数。把修改后的文件保存一份，并确认能找到它。然后回到原对话，输入“请再帮我起一个更简短的标题”，先不要发送。

参与者可以使用自己的措辞。若询问活动内容或修改要求，只重复任务和源文件信息；不讲解“预览”“采用”“版本”等产品词、不指向控件、不代替鼠标或键盘操作。观察人可因越出测试目录、涉及私人数据或其他安全原因中止，并原样记录中止原因。

## 每场观察怎么记录

从参与者开始操作时计时。只记录真实行为，卡住时先让参与者表达期待的结果。允许自行恢复的错点；如需他人接管或术语教学，保留失败记录，不用之后的教学重试覆盖它。若安装、模型不可用等条件不满足，记为“条件不足”，修复后另开记录，不能直接写成功。

| 步骤 | 观察证据 | 本场结果 |
| --- | --- | --- |
| 新对话和源文件 | 自行开始新对话并添加指定文件；记录犹豫或误解 | 待观察 |
| 一次原生授权 | 实际操作名称、请求范围、参与者选择、完成后是否仍在原对话 | 待观察 |
| 阅读内容与来源 | 能找到并阅读实际生成的 Markdown 与源文件关系；检查时间、人数及未确认事项 | 待观察 |
| 修改 | 在原对话提出修改；实际文件出现勾选清单且保留原始事实 | 待观察 |
| 保存 | 应用报告的受管保存位置存在可读取的实际副本，内容与选择的修改版本一致 | 待观察 |
| 返回并保留草稿 | 仍是原对话；指定标题请求留在输入框中且未发送 | 待观察 |
| 完整性 | 选中的对话、源文件、结果和未发送草稿没有丢失；无术语教学、代操作 | 待观察 |

当前产品把副本保存到受管位置；本任务不要求任意选择保存目录，原生 Save As 仍属[后续验收范围](familiar-work-v5.md)。观察人不可因未提供原生 Save As 将该步骤判失败，也不可把文件代为复制后计为参与者完成。

每场另记：参与者编号、已有 DSH 使用经历、所用包名及 SHA-256、完整提交 SHA、平台、窗口大小、开始与结束时间、观察人、直接引语和恢复路径。截图或录屏只保留虚构任务内容，输出文件及可重现问题与该场编号对应。
