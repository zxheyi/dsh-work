状态：实现基准

关联事实源：[`DSH Work 产品定位 PRD`](../../../DSH%20Work%20设计稿/prd.html)、[`ADR 0006`](../decisions/0006-work-as-product-owned-aggregate.md)、[`首页设计规格 v1`](work-home-v1.md)

真实渲染：[`work-home-v2.actual.png`](work-home-v2.actual.png)，由官方 Harness Profile 在 1440 × 900 CSS px 视口中加载 Work Client，并展开“添加资料”菜单后截取。

令牌数据：[`work-home-v2.tokens.json`](work-home-v2.tokens.json)

## 本版结论

首页不要求用户选择 Work 目录。创建 Work 时，DSH Work 自动拥有并管理一个 Workspace；普通用户只需要描述目标，并按需添加资料。Workspace 路径、Primary Session 和 Turn 都属于恢复与执行机制，不进入创建流程。

v2 将 v1 的“添加文件 / 添加网页 / 粘贴内容”三个平铺按钮收拢为一个“添加资料”入口：

1. 降低首次创建 Work 时的决策负担。
2. 增加“添加文件夹”，但不把文件夹等同于 Work Workspace。
3. 为文件、文件夹、网页和粘贴内容提供统一入口。
4. 保留拖入文件或文件夹的目标交互，不新增“选择工作目录”。

未列出的画布、栅格、颜色、字体、侧栏、顶栏、常见工作和最近工作规格全部继承 v1。

菜单默认向上展开，使主按钮、常见工作和最近工作保持可见。它是临时浮层，关闭后不改变创建器布局。小于 720 px 时菜单宽度不超过 `视口宽度 - 48 px`。

## 文案

- 创建器说明：`描述想要的结果，资料可以稍后添加。`
- 文本框占位：`描述目标，或将文件和文件夹拖到这里（即将支持）`
- 入口：`添加资料`
- 菜单项：`添加文件`、`添加文件夹`、`添加网页`、`粘贴内容`
- 当前阶段辅助说明：`可选，文件和文件夹即将支持`

方向稿表达完整目标交互。当前第一阶段实现中，四个资料菜单项均显示“即将支持”并保持禁用，不能让用户误以为资料已进入 Workspace。真正接入资料后，移除对应项的阶段提示和禁用态。

## 状态与交互

- 点击“添加资料”展开或收起菜单。
- `Enter` 或 `Space` 可操作入口，`Tab` 可进入菜单项；禁用项仍须清楚可读。
- 菜单采用产品语言，不出现 Workspace、Session、Agent、模型或插件。
- 文件和文件夹是 Work 的输入资料，不是 Workspace 所有权选择。
- 拖拽目标态：文件经过创建器时显示 2 px 钴蓝边框和浅蓝背景；离开或放下后恢复。
- 当前第一阶段只展示拖拽认知，不消费文件数据，也不改变 Harness 的 Workspace。
- 资料能力接入后，文件夹默认作为资料快照导入 DSH Work 管理的 Workspace；不直接把用户原目录变成 Workspace。
- “开始工作”仍是唯一主操作，资料入口始终保持次级层级。

## 验收

1. 1440 × 900 首页只展示一个“添加资料”入口，不再平铺三个资料按钮。
2. 展开菜单恰好包含文件、文件夹、网页和粘贴四类资料。
3. 页面没有 Work 目录或 Workspace 路径选择控件。
4. 当前未接入的菜单项必须明确显示“即将支持”。
5. 创建 Work、继续 Work、状态恢复和 Harness Slot 替换行为不因本次视觉调整而改变。
6. 实际 Harness 展开态渲染必须固化为 `work-home-v2.actual.png`。
